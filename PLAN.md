# План работ — Git Flow Ops

Цель: довести команды из `SPEC.md` до версии, которую можно установить и обновлять
в EDT 2025.2.6 на Windows без ручного копирования JAR. Первая версия
зафиксирована коммитом `cc28aea`; Quick Stash проверен пользователем в Windows.
Preview 0.4.5: команды реализованы и 30 headless-тестов проходят на Mac;
следующие пункты остаются открытыми до проверки указанных краевых случаев и EDT.

## 1. Получение и отправка

- [ ] Smart Pull: fetch → безопасное обновление ветки → восстановление локальных
  изменений; проверить актуальную ветку, новый коммит, dirty tree, конфликт,
  отсутствие upstream и недоступный remote.
- [ ] Smart Push: тот же предварительный контроль, затем push без force; проверить
  успешную отправку, отсутствие новых коммитов и push rejected.
- [ ] «Подтянуть все проекты»: один запуск на каждый уникальный репозиторий,
  отчёт по каждому; ошибка одного не останавливает остальные.

## 2. Веточные операции

- [ ] Smart Checkout (§5.7): чистое/грязное дерево, новая/существующая ветка,
  конфликт apply со сохранением стеша.
- [ ] Undo Last Commit (§5.6): soft/mixed, merge-коммит, отсутствие родителя,
  предупреждение для уже отправленного коммита.
- [ ] Commit to New Branch (§5.4): валидация ветки, staged/unstaged,
  возврат на исходную ветку и отказ без потери изменений.
- [ ] Move Last Commit to Branch (§5.5): cherry-pick, очистка исходной ветки
  только после успеха, конфликт и запрет для небезопасных случаев.

## 3. Команды для повседневной работы

- [ ] «Безопасный коммит» (§5.10): защита веток и шаблон сообщения.
- [ ] Генератор сообщения (§5.11): ключ задачи из имени ветки.
- [ ] Ссылки на GitLab (§5.12): файл, ветка и коммит; URL с URL-encoding.
