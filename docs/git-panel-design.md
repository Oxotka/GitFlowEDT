# Основная Git-панель EDT — проект интерфейса

Статус: на обсуждении. Цель — повседневная работа с Git в одной перемещаемой
вкладке Eclipse вместо нынешней панели «Операции». Штатное «Индексирование Git»
остаётся доступным для расширенных действий, но не требуется для обычного цикла.
Это сознательно меняет прежнее правило `SPEC.md` не дублировать staging:
здесь единая компактная работа с файлами важнее сохранения отдельного окна.

## Рабочий сценарий

Разработчик открывает EDT и видит текущий репозиторий, ветку и изменения. Он
просматривает diff нажатием на файл, готовит нужные файлы кнопкой `+`, пишет
сообщение и нажимает **Commit & Push**. Плагин создаёт локальный коммит, затем
проверяет удалённую ветку, получает новые коммиты при необходимости и отправляет
без force. Отдельная кнопка **Sync** нужна для уже созданных локальных коммитов.

Репозиторий выбирается по текущему проекту, иначе первый доступный. Список
появляется только при нескольких репозиториях. Панель сохраняет работоспособность
при размещении слева или снизу; её элементы не растягиваются на всю высоту окна.

## Компоновка

```text
 npo  ·  releases/3.0.207        ↓0 ↑2      ⟳  ⋯

 Сообщение коммита
 [ Исправить расчёт даты                       ]
 [               Commit & Push                 ]

 Подготовлено · 2                         − всё
   M  ОбщийМодуль.bsl                         −
   A  НовыйФайл.bsl                           −

 Изменения · 3                            + всё
   M  Форма.xml                               +
   U  README.md                               +
   U  .DS_Store                               +

 Готово к отправке: 2 коммита
```

- Нажатие на имя ветки открывает существующий выбор веток: избранные первыми,
  затем дерево по `/` и поиск. Нажатие на файл открывает diff. Статус `M/A/D/U`
  показан текстом вместе с иконкой, чтобы смысл не зависел только от цвета.
- Секции сворачиваются. Пустая «Подготовлено» скрыта. `+` и `−` доступны у
  строки и с клавиатуры; наведение мыши не является единственным способом
  вызвать действие. Групповые действия имеют подписи-подсказки.
- `⟳` — **Sync**: получить, затем отправить уже созданные коммиты. В `⋯`
  находятся отдельные Pull, Push, Fetch, stash и редкие веточные действия.
  Подсказка к ↓/↑ говорит, что числа основаны на последнем fetch.
- Вкладка не содержит постоянно открытого большого журнала, полей автора или
  коммиттера. Короткий итог операции показан под списками; подробности и
  восстановление доступны по ссылке из сообщения.
- Если изменений нет, списки заменяются одной строкой «Нет изменений» без
  пустых областей. Панель следует теме EDT и не задаёт собственные цвета шрифтов.

## Правила действий

**Commit & Push.** Если есть подготовленные файлы, коммит включает только их.
Если подготовленных файлов нет, панель предлагает подготовить отслеживаемые
изменения с видимым перечнем. Новые файлы не добавляются молча: их выбирают
кнопкой `+`. Сообщение обязательно; ключ задачи из имени ветки предлагается,
но не блокирует коммит без такого ключа. Защищённая ветка требует подтверждения.

После успешного коммита начинается умная отправка: fetch → безопасное получение
при необходимости → push без force. Если получение или отправка не удались,
коммит остаётся локально. Сообщение объясняет это и предлагает **Sync**;
повторное нажатие не создаёт дублирующий коммит. Если remote не настроен,
основная кнопка называется **Commit**, результат явно сообщает, что коммит
остался локальным. Настройка «Отправлять после коммита» включена по умолчанию;
при выключении кнопка также называется **Commit**.

**Переключение ветки.** Можно выбрать ветку при наличии подготовленных,
неподготовленных и новых файлов. Плагин переносит их автоматически и после
успеха сохраняет распределение между секциями «Подготовлено» и «Изменения».
Ручной stash для обычного переключения не нужен. Если перенести правки нельзя,
плагин не удаляет временное сохранение, сообщает, на какой ветке находится
пользователь, где лежат правки и как их восстановить. Опасный конфликт не
маскируется сообщением об успешном переключении.

**Sync.** Работает без нового коммита: проверяет сервер, получает при
необходимости и отправляет локальные коммиты. При конфликте панель показывает
остановленную операцию и путь к её разрешению или отмене.

## Граница реализации

Новая вкладка заменяет содержимое «Операций». Git-операции и состояние файлов
остаются в `core` на JGit; UI строится на SWT/JFace. Diff открывается редактором
Eclipse через публичные API, без обращения к классам `org.eclipse.*.internal`.
Существующий выбор веток и механизм безопасного переключения переиспользуются;
в тесты добавляется проверка сохранения staged/unstaged после смены ветки.

## Проверка удобства и корректности

1. В EDT с одним репозиторием после открытия панели нет выбора репозитория и
   пустого экрана. При нескольких выбранный проект задаёт контекст.
2. Добавление файла в индекс, исключение из индекса, просмотр diff, ввод
   сообщения и Commit & Push доступны из одной панели без модальных окон об
   успехе. Новые файлы не попадают в коммит без явного выбора.
3. После переключения ветки с одновременно подготовленными, неподготовленными
   и новыми файлами содержимое и состояние индекса сохраняются. При конфликте
   ни одна правка не теряется; панель показывает конкретный следующий шаг.
4. После неудачной отправки локальный коммит виден как исходящий, повторный
   Sync не создаёт второй коммит. Отсутствующий remote объяснён в интерфейсе.
5. На Windows EDT 2025.2.6 панель проверена в узкой и широкой вкладке, мышью
   и клавиатурой. Кнопки с иконками имеют понятные подсказки и видимый фокус.
