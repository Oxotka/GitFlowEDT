# Обзор Git-клиентов и ориентиры для Git Flow

Документ сохраняет первичный обзор популярных Git-клиентов и принципы отбора идей для плагина Git Flow в 1C:EDT. Его можно дополнять по мере исследования конкретных сценариев.

## Цель Git Flow

Git Flow не должен становиться универсальным клиентом со всеми возможными Git-функциями. Наша цель — дать минимально необходимый набор, который хорошо встраивается в повседневный рабочий процесс 1C:EDT и использует возможности Eclipse там, где это уместно.

Приоритеты проектирования:

1. **Удобство** — действие понятно, находится рядом с нужным контекстом и не мешает работе с проектом 1С.
2. **Производительность** — интерфейс быстро отвечает и не блокирует EDT на долгих операциях.
3. **Функциональность** — добавляем возможности только при наличии понятного сценария и заметной пользы.

Наличие функции в другом Git-клиенте само по себе не является основанием для её реализации. Для каждой идеи нужно определить сценарий пользователя, проверить возможности штатного EDT/EGit, оценить ограничения Eclipse/SWT и стоимость поддержки.

## Краткий обзор решений

| Решение | Основные сильные стороны | Идеи для изучения в контексте Git Flow |
| --- | --- | --- |
| **SourceTree** | Граф коммитов и веток, Git Flow, интерактивный rebase; интеграция с экосистемой Atlassian | Насколько полезны действия над ветками и коммитами прямо из контекста графа |
| **GitHub Desktop** | Простой поток «изменения → просмотр diff → коммит → синхронизация»; история и переходы к PR | Простая и ясная подача текущего состояния репозитория и связанных PR |
| **GitKraken / GitLens** | Визуальная история, поиск и сравнение коммитов, интеграция веток с PR/MR и хостингами | Поиск по истории, контекст ветки, быстрый переход к MR |
| **Fork** | Быстрый настольный интерфейс, навигация по истории и операции над коммитами | Отзывчивость и короткий путь от выбранного коммита к его diff и действию |
| **Tower** | Визуальная помощь при конфликтах, история refs, восстановление отдельных Git-состояний через reflog | Как показывать потенциально сложные операции и помогать безопасно восстанавливаться |
| **SmartGit** | Настраиваемый граф, развитая работа с refs, интеграции с GitLab, GitHub, Bitbucket и Gerrit | Настройка отображения refs и компактное представление связанной информации хостинга |
| **lazygit** | Клавиатурная навигация, поиск в истории с контекстом, быстрые действия из списков | Поиск коммитов по пути и перемещение между совпадениями с сохранением контекста графа |

Это качественный обзор заявленных возможностей продуктов и повторяющихся пользовательских предпочтений, а не рейтинг долей рынка. Надёжного нейтрального сравнения по числу пользователей в рамках этого обзора не найдено. В обсуждениях разработчики часто отмечают пользу визуального просмотра diff перед коммитом, графа веток/коммитов и быстрого доступа к действиям из выбранного контекста; предпочтения зависят от привычного рабочего процесса.

## Перспективные темы для Git Flow

### Поиск по истории

Поиск по истории уже оформлен отдельной задачей. При анализе UX стоит дополнительно сравнить:

- выдачу только совпадающих коммитов и навигацию по совпадениям с сохранением соседних коммитов в графе;
- поиск по пути/файлу и его ценность для поиска истории конкретного объекта 1С;
- поиск по метаданным коммита и более дорогой поиск по содержимому diff.

### Связь ветки с Merge Request

Интеграция с GitLab оформлена отдельной задачей. В качестве UX-ориентира изучить GitLens и lazygit: показать связанный PR/MR и его состояние у ветки, дать прямой переход к странице запроса. Для нас целевой сценарий — GitLab, включая Self-Managed; необходимо отдельно учитывать доступность API и авторизацию.

### Обзор истории и действий

До реализации нового графа или панели проверить штатную историю ЕДТ/EGit и текущую историю Git Flow. Улучшения должны решать конкретную задачу пользователя и учитывать ограничения Eclipse/SWT, а не копировать структуру отдельного настольного Git-клиента.

## Что не переносим автоматически

- **Частичную индексацию строк и hunk’ов** не рассматриваем как целевую функцию Git Flow. Для сценариев 1С она не является приоритетной и в некоторых случаях может привести к нежелательному частичному коммиту.
- **Worktrees** ранее решили не включать в рассматриваемый набор.
- **Интерактивный rebase, bisect и массовое редактирование истории** требуют отдельного обоснования реальным сценарием, анализа штатных возможностей EDT/EGit и оценки риска для пользователя.
- Наличие AI или интеграции с хостингом в другом клиенте не означает, что нужно создавать собственный сервис. Для Напарника заведена отдельная задача на исследование доступного способа интеграции.
