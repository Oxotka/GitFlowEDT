# Инструкции для работы с репозиторием

## Проект

Git Flow — плагин для 1C:EDT. Исходники на Java 17, сборка Eclipse/PDE-плагина
выполняется Maven и Tycho.

Перед изменениями смотри документацию и текущую реализацию:

- `README.md` — возможности, установка и сборка;
- исходный код и git-историю — детали устройства и принятые решения.

## Принципы проектирования функций

- Цель Git Flow — минимально необходимый и удобный набор возможностей для
  повседневного рабочего процесса в 1C:EDT, а не универсальный Git-клиент.
- Приоритеты: **удобство**, затем **производительность**, затем
  **функциональность**.
- Перед добавлением функции определи конкретный пользовательский сценарий,
  проверь возможности штатных EDT/EGit и оцени ограничения Eclipse/SWT,
  производительность и стоимость поддержки.
- Не добавляй функцию только потому, что она есть в другом Git-клиенте.
  Выбирай и проектируй её с учётом сценариев 1С и реальной пользы пользователю.

## Проверка и сборка

- Полная проверка: `mvn verify` (нужны JDK 17–21, Maven 3.9+ и EDT для target-платформы).
- Проверяй итоговый установочный архив: `unzip -t <путь-к-архиву>`.
- Для изменений плагина запускай полный набор core-тестов вместе с полной сборкой.
- Не считай совместимость с версией EDT подтверждённой только потому, что сборка
  или установка прошла на другой версии.

## Инварианты Git-операций

- Не теряй staged, unstaged и untracked изменения. Перед операцией, которая может
  их затронуть, используй проверенную логику сохранения изменений. Не удаляй stash,
  пока его применение не завершилось успешно; при конфликте оставь его и сообщи ID.
- Не добавляй force push. Не переписывай опубликованную историю незаметно для
  пользователя. Не запускай обычные операции в репозитории во время rebase, merge
  или cherry-pick; сначала проверь состояние репозитория.
- Держи основную Git-логику в `dev.edt.gitflow.core`, отдельно от SWT/UI. Долгие
  Git-операции запускай вне UI-потока через Eclipse Jobs; покрывай core-тестами.
- UI использует некоторые внутренние API EGit, которые могут меняться между
  версиями EDT. При их изменении сохраняй штатное действие EDT как fallback и
  проверяй затронутые версии вручную.
- Не меняй OSGi `Bundle-SymbolicName` и ID feature без необходимости: это влияет
  на распознавание и обновление установленного плагина. Новые UI-строки добавляй
  и в английские, и в русские ресурсы.

## Сборка и релиз

- `releng/edt-2026-1.target` сейчас содержит локальный путь к EDT на macOS.
  На другой машине его нужно заменить на каталог `plugins` установленной EDT,
  прежде чем собирать исходники. Это не влияет на установку готового p2 ZIP.
- Один p2 ZIP содержит плагины Git Flow и метаданные установки; не вкладывай в
  него саму EDT или системные библиотеки.
- Текущая версия — 0.8.8. При новом релизе синхронно обновляй версии в Maven
  POM-файлах, OSGi-манифестах и `dev.edt.gitflow.feature/feature.xml`.
- Не коммить собранные ZIP-архивы. Публикуй их как assets GitHub Release только
  по прямой просьбе пользователя.
- Не коммить и не пушь без прямой просьбы. Не добавляй локальные скриншоты,
  кеши, секреты и настройки машины без проверки и согласования.
- Коммиты пиши по-русски, без `Co-Authored-By`.

## Что считать подтверждённым

Если тесты или версия EDT не проверены, так и указывай — не выдавай заявленную
совместимость за фактически проверенную. Основное описание и текущий статус
проверок поддерживай в `README.md`.
