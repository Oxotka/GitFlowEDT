# Git Flow Ops

Плагин потоковых Git-операций для 1C:EDT. **Спека — `SPEC.md`** (архитектура,
спецификации команд, критерии приёмки, дорожная карта). Этот README — только
по установке и сборке.

## Требования

- JDK 17+ (для сборки подойдёт 17–21).
- Maven 3.9+ — системный или локальный из `.tools/` (см. ниже).
- Локальная установка EDT 2026.1 (пути — в `releng/edt-2026-1.target` и `SPEC.md §3`).

## Сборка

```bash
# вариант 1: системный Maven
mvn verify

# вариант 2: локальный Maven (если не установлен)
curl -fsSL https://archive.apache.org/dist/maven/maven-3/3.9.9/binaries/apache-maven-3.9.9-bin.tar.gz \
  | tar -xz -C .tools --strip-components=1
.tools/bin/mvn verify
```

Target platform берётся из p2-пула EDT (`releng/edt-2026-1.target`,
Directory-location на `~/.p2/pool/plugins`). При переносе на другую машину
поправьте путь в этом файле.

> **Архитектура**: EDT 2026.1 на этой машине — x86_64 (Rosetta). В p2-пуле
> SWT-классы лежат в платформенном фрагменте `org.eclipse.swt.cocoa.macosx.x86_64`,
> поэтому в `pom.xml` среда резолва зафиксирована `macosx/cocoa/x86_64`. Если EDT
> станет нативным arm64 — поменять `<arch>` в `target-platform-configuration`.

## Установка в EDT на Windows

Текущая версия для локальной проверки — `dist/gitflow-ops-0.4.9-preview.zip`.
Это p2-репозиторий: архив не нужно распаковывать или копировать в `plugins`.

1. Закройте EDT. Если была установлена первая версия через `dropins`, удалите
   папку `<каталог EDT>\1cedt\dropins\gitflow` целиком. При установке через
   EDT Start каталог EDT обычно находится в
   `%LOCALAPPDATA%\1C\1cedtstart\installations\<версия EDT>`.
2. Запустите EDT → **Справка → Установить новое ПО…** → **Добавить…** →
   **Архив…** и выберите `gitflow-ops-0.4.9-preview.zip`.
3. Выберите **Git Flow Ops**, завершите мастер и перезапустите EDT.
4. Откройте **Git Flow Ops → Открыть Git-панель**. Её также можно открыть через
   **Окно → Показать представление → Другие… → Git Flow Ops → Git**.

В штатном **Индексировании Git** кнопка **Фиксировать и отправить** также
использует Smart Push: EGit создаёт коммит со своими настройками автора, затем
плагин проверяет удалённую ветку, получает новые коммиты при необходимости и
отправляет изменения. Если подготовленных файлов нет, кнопка синхронизирует уже
созданные коммиты. На ветке без upstream потребуется подтверждение. Адаптер
использует внутренний обработчик EGit; если в установленной версии EDT он
изменился, штатное действие кнопки сохраняется, а ошибка попадёт в
**Журнал ошибок**. Это поведение ещё нужно проверить в EDT 2025.2.6.
Во время Smart Push плагин показывает его название на кнопке и скрывает
промежуточные кнопки rebase. Если операция остановится на конфликте, штатные
кнопки станут доступны после обновления панели.

Наша панель сразу выбирает текущий репозиторий или первый доступный. При нескольких
репозиториях появляется список для переключения. Изменения и подготовленные файлы
находятся в одном дереве с постоянными заголовками групп: **+** добавляет файл
в коммит, **−** убирает из него. Файл сразу перемещается в нужную группу;
после операции панель проверяет фактическое состояние Git. Основная
кнопка при изменениях создаёт коммит, затем проверяет сервер и отправляет его.
Сообщение коммита вводится над кнопкой. Если изменений нет,
основная кнопка выполняет **Sync Changes**. Отправку после коммита можно отключить
в меню **⋯**; там же доступны отдельные команды получения и отправки.

У изменённого отслеживаемого файла есть действие **↶** — «Вернуть файл к
последнему коммиту». Оно отменяет и подготовленные, и неподготовленные правки
этого файла после подтверждения. Новые файлы и конфликты таким действием не
удаляются. Правый щелчок по строке открывает сравнение, подготовку или исключение
из коммита и, где доступно, возврат файла.
Нижняя строка показывает короткий результат операции; полный текст и адреса
открытых ссылок доступны в **⋯ → История операций**.
Над строкой результата находится компактная история текущей ветки: последние
30 коммитов с графом и двухстрочными сообщениями; автор показан в конце второй
строки. Наведите указатель на коммит, чтобы
увидеть дату, хеш и полный текст. Разделитель между файлами и историей можно
перетаскивать, меняя высоту областей.

Нажатие на название ветки вверху панели открывает выбор ветки с группировкой и
избранным. Папка «Избранное» всегда первая. Выберите ветку и нажмите
**☆ В избранное**, чтобы она появилась в этой папке. Папки отмечены значками.
Для создания ветки нажмите ссылку под списком — откроется поле имени. Папку
удалённых веток можно закрепить через её контекстное меню: она появится первой
в разделе удалённых веток. Команда
переключения есть и в контекстном меню проекта **Team**. Штатный диалог EGit
«Ветки» остаётся отдельным и не показывает избранное плагина.

Команды доступны также в меню **Git Flow Ops** и частично в контекстном меню
проекта **Team**. На новой ветке без upstream отправка запросит подтверждение и
настроит связь с `origin`. Повторный запуск операции для того же репозитория
блокируется.

Если открыть штатное **Индексирование Git** без выбранного проекта, плагин
подставит первый репозиторий рабочего пространства. Если EGit уже выбрал
репозиторий, выбор сохраняется.

В командах «Переключиться на ветку» и «Перенести последний коммит» ветки показаны
деревом по частям имени (`feature/`, `release/`), с поиском и избранным для каждого
репозитория. Избранное — первая папка и остаётся видимым при поиске. Стрелка вниз
переводит из поиска к веткам, Enter и двойной щелчок выбирают ветку. Для
переключения доступны также удалённые ветки: плагин пояснит, будет ли создана
локальная tracking-ветка. Слияние выполняет штатный EGit.

В штатном окне EGit **«Слить»** плагин подставляет то же дерево веток с поиском,
избранным и закреплёнными папками. Настройки и выполнение слияния остаются
штатными. Ссылка под деревом возвращает исходный выбор EGit для тегов и других
ссылок. Если структура диалога в версии EDT несовместима, остаётся исходный
список EGit.

При нескольких репозиториях без выделения команды работают с выбранным в панели
Git или первым в списке; для другого сначала выберите его проект или
репозиторий в панели. Если установка
сообщает о несовместимых зависимостях, сохраните текст ошибки: новые команды
собраны на EDT 2026.1.1 и пока не проверены в EDT 2025.2.6 на Windows.

Старый `dist/gitflow-ops-0.1.0-local.zip` оставлен только для воспроизведения
первой версии, которую пользователь уже проверил в Windows.

## Отладка (PDE)

1. Импортировать проекты в workspace EDT (Import → Existing Projects).
2. Открыть `releng/edt-2026-1.target` → Set as Target Platform (дождаться резолва).
3. Run → Run Configurations → Eclipse Application → продукт
   `com._1c.g5.v8.dt.product.application.rcp` → Run (поднимется второй экземпляр EDT
   с плагином из workspace).

## Структура

```
dev.edt.gitflow.core   — headless-логика (JGit), без UI
dev.edt.gitflow.ui     — команды, меню, панель и диалоги
releng/                — .target-платформа, launch-конфигурации
SPEC.md                — спецификация (читать первым)
```

## Совместимость

Сборка и headless-сценарии проверены с EDT 2026.1.1 на macOS. В целевой
EDT 2025.2.6 на Windows пользователь подтвердил загрузку версии 0.1.0 и работу
Quick Stash. Совместимость новых команд и p2-установки версии 0.4.9 на Windows
пока требует ручной проверки.
