# HANDOFF — состояние Git Flow Ops

Дата: 2026-10-01. Основная спецификация — `SPEC.md`; порядок оставшихся работ —
`PLAN.md`; инструкция для установки — `README.md`. Целевая среда пользователя:
Windows, EDT 2025.2.6. Mac с EDT 2026.1.1 используется для разработки и сборки.

## Что готово

- Фаза 0 и первая версия Quick Stash / Quick Pop сохранены коммитом `cc28aea`.
  Пользователь установил 0.1.0 через `dropins` в Windows EDT 2025.2.6 и
  подтвердил работу Quick Stash. Остальные сценарии 0.1.0 вручную не проверялись.
- В текущем дереве реализованы Smart Pull, Smart Push (проверка и получение перед
  отправкой), Pull All, Smart Checkout, Undo Last Commit, Commit to New Branch,
  Move Last Commit to Branch, Safe Commit, генератор сообщения и ссылки на GitLab,
  GitHub и Bitbucket. Подтверждение остаётся для переписывания опубликованной
  истории и коммита в защищённую ветку. Core-тесты работают на временных Git-репозиториях.
- В preview 0.4.3 представление «Git» заменяет прежнюю панель «Операции»:
  подготовленные и остальные изменения в одном дереве, индексация файлов
  через +/− с немедленным обновлением интерфейса и последующей сверкой с Git, поле
  сообщения и адаптивная кнопка Commit & Push / Commit / Sync Changes. Отправка
  после коммита включена по умолчанию и отключается в меню ⋯. Там же отдельные
  Pull/Push и история результатов. Формы подтверждения пока модальные.
- У изменённого отслеживаемого файла в группе «Изменения» есть ↶: после
  подтверждения JGit возвращает индекс и рабочий файл к HEAD. Новые файлы и
  конфликты не удаляются. Контекстное меню строки содержит сравнение,
  подготовку/исключение и доступный возврат к последнему коммиту.
- Нижний статус стал однострочным: открытые URL показываются кратко, полный
  текст сохраняется в истории операций через ⋯.
- Репозиторий выбирается автоматически, переключатель виден при нескольких
  репозиториях. Нажатие на текущую ветку открывает наш выбор веток. Штатный
  диалог EGit не менялся и не показывает избранное плагина. Команды добавлены
  также в Team-меню проекта с пометкой Git Flow Ops.
- В preview 0.4.3 при открытии пустого штатного Git Staging выбирается первый
  репозиторий. У EGit нет публичного API для этого действия; адаптер вызывает
  его публичные методы `getCurrentRepository` и `reload` через reflection,
  не вмешиваясь в уже сделанный выбор. Проверить на Windows EDT 2025.2.6.
- Для ветки без upstream Smart Pull предлагает связать одноимённую ветку origin,
  Smart Push — связать существующую или опубликовать новую. Оба действия требуют
  подтверждения; force push не используется.
- Добавлены Tycho feature и p2 repository. ZIP для установки через мастер EDT:
  `dist/gitflow-ops-0.4.3-preview.zip`; старый dropins ZIP сохранён для истории.
- Для переключения и переноса коммита есть дерево веток с поиском и избранным
  по репозиторию. Удалённая ветка создаёт локальную tracking-ветку. Для merge
  тот же выбор потребуется после реализации самой команды слияния.
  Избранное — первая папка общего дерева даже когда оно пусто; поиск её не скрывает. Диалог помечает
  текущую ветку и поясняет результат выбора удалённой ветки.

## Проверено

- `.tools/bin/mvn -B -o -Dmaven.repo.local=/private/tmp/gitflow-m2-review verify`
  на Mac: BUILD SUCCESS, 29 JUnit-тестов, включая статус репозитория, pull/push, стеш, checkout,
  перенос коммита, safe commit и ссылки.
- p2 ZIP содержит feature, оба бандла и metadata; `unzip -t` проходит.
- `git diff --check` проходит. Ручная установка и новые команды 0.4.3 в Windows
  EDT 2025.2.6 **ещё не проверены**; возможны различия в зависимостях EDT.

## Как продолжать

1. Для сборки используется локальный `.tools/bin/mvn` (Maven 3.9.9), системный
   JDK 21, JavaSE-17 в манифестах. Target: `releng/edt-2026-1.target`, локальный
   `~/.p2/pool/plugins`. Машина arm64, EDT x86_64 под Rosetta, поэтому в `pom.xml`
   задан `macosx/cocoa/x86_64` для Tycho.
2. До выпуска проверить p2-установку ZIP и команды на Windows EDT 2025.2.6.
   Перед установкой 0.4.3 удалить старую `dropins/gitflow` согласно README.
3. Для массового выпуска нужен независимый от локального p2-пула build target,
   регрессионные сценарии конфликтов и проверка обновления через p2. Не считать
   preview-архив публичным релизом.
4. Не добавлять других зависимостей от `org.eclipse.*.internal` API. После правок: `mvn verify`,
   `git diff --check`, проверка ZIP. Коммиты — на русском, без Co-Authored-By;
   push только после успешных проверок и отдельного поручения пользователя.

## Известные ограничения

- Для создания новой ветки остаётся поле ввода. Команды merge пока нет.
  Просмотр diff из панели и новый интерфейс требуют ручной проверки на Windows.
- Текущая target-платформа — EDT 2026.1.1. Версия 2025.2.6 проверена только
  пользователем для старого Quick Stash; результаты новых команд ждут ручного теста.
- Push/Fetch используют стандартные настройки JGit/EGit; сценарии авторизации
  и серверных отклонений требуют проверки в реальной EDT.
